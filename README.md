# Genotek → GEDCOM

Расширение Google Chrome добавляет на страницу [древа Genotek](https://lk.genotek.ru/genealogical-tree) кнопку **«Скачать GEDCOM»**. Формат — **GEDCOM 5.5.1, UTF-8**, файл `.ged`.

## Установка в Chrome через режим разработчика

1. На странице этого репозитория откройте **Releases** и выберите последнюю версию.
2. В разделе **Assets** скачайте **Source code (zip)** — GitHub автоматически добавляет этот архив к релизу.
3. **Распакуйте архив** в удобную папку на компьютере.
4. Откройте Google Chrome и введите `chrome://extensions` в адресную строку.
5. Включите **Режим разработчика** в правом верхнем углу и нажмите **Загрузить распакованное расширение**.
6. Внутри распакованного репозитория выберите папку **`extension`**. В ней должен находиться файл **`manifest.json`**. Выбирать весь репозиторий, сам ZIP или файл `manifest.json` не нужно.
7. Убедитесь, что в списке появилось расширение **Genotek → GEDCOM** и оно включено.
8. Войдите в Genotek и откройте [страницу древа](https://lk.genotek.ru/genealogical-tree) в режиме **«Древо»**. **Если она уже открыта, обновите вкладку**. В правой панели нажмите кнопку с рисунком листа, стрелкой вниз и надписью **GEDCOM** под рисунком — она расположена сразу под штатной кнопкой скачивания PDF. При наведении или выборе клавишей Tab появится подсказка **«Скачать GEDCOM»**.

Если скачали репозиторий через **Code → Download ZIP** или клонировали его, также выбирайте папку **`extension`**.

Node.js, сборка проекта и Tampermonkey для установки не нужны. Сохраняйте выбранную папку на месте: Chrome загружает расширение из неё.

Для обновления замените файлы в выбранной папке новой версией, откройте `chrome://extensions` и нажмите значок **Перезагрузить** на карточке расширения. Затем обновите вкладку Genotek.

Порядок загрузки и обновления описан также в [официальной инструкции Chrome](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked).

## Что происходит при скачивании

Если выбран фильтр «Близкие», «Прямые» или «Кровные», расширение переключает его на **«Все»**, ждёт ответ Genotek и проверяет число людей. После экспорта режим «Все» остаётся выбранным.

Начиная с **1.0.1**, расхождение счётчика не мешает экспорту, если расширение подтвердило, что сайт отправил запрос полного древа (`full: true`, без фильтров или выбранной ветви), а связи карточек корректны. Экспортируются все фактически полученные карточки; расхождение явно указано в сообщении расширения. Причину расхождения на сервере расширение установить не может.

Если счётчики расходятся, а полный запрос не подтверждён, экспорт останавливается. При совпадении счётчиков отдельное подтверждение полного запроса не требуется. Ссылки на отсутствующих людей, дубликаты идентификаторов и циклы родителей всегда останавливают экспорт. Сравнение счётчика само по себе не позволяет доказать, что сервер не пропустил изолированную карточку.

В выгрузку входят:

- имена, отчества, фамилии, варианты имён и девичьи фамилии;
- пол, даты и места рождения/смерти с координатами, когда они указаны;
- национальность из поля «Этнический состав» карточки;
- родители, дети, партнёры, официальные браки и разводы;
- пользовательские примечания и биографический текст, если они присутствуют в ответе графа;
- род занятий, образование и исходные идентификаторы карточек.

Семьи строятся по точной паре родителей. Сведения об одном известном родителе не дополняются вымышленным супругом. Неизвестный пол остаётся `U`. Неполные даты сохраняют точность: `1900`, `FEB 1900`, `12 FEB 1900`. Если проверка даты возвращает ошибку, значение не попадает в файл, а расширение показывает предупреждение.

Незаполненные поля пропускаются, включая строки из одних пробелов. Нет национальности — нет `NATI`; нет даты рождения — нет её `DATE`; нет места рождения — нет его `PLAC`. Если не заполнены ни дата, ни место рождения, блок `BIRT` целиком отсутствует. Нераспознанные даты пропускаются с предупреждением; ограничение для повреждённых объектов даты описано в [документации](docs/README.md#даты-datesjs). Обработка строк из пробелов исправлена в **1.0.5**.

С версии **1.0.2** структурированные места преобразуются в читаемые названия: например, **«Россия, Тульская область, город Тула»**. Почтовый индекс, ISO-коды, федеральный округ и служебные показатели не включаются в название. «Село», «деревня» и другие типы уточняются по исходному адресу и данным Genotek. Неизвестные типы не угадываются; нераспознанный адрес без координат остаётся как был.

Координаты берутся из Genotek без геокодирования и записываются в `PLAC → MAP → LATI/LONG`, со сторонами света `N/S` и `E/W`. Нужны обе корректные координаты; нулевые значения допустимы. Ниже учебный пример с вымышленными координатами:

```gedcom
2 PLAC Россия, Тульская область, город Тула
3 MAP
4 LATI N54.1234567
4 LONG E37.7654321
```

Для события выгружаются первые подходящие дата и место; при дополнительных вариантах расширение показывает предупреждение, но не создаёт служебный `NOTE`. Национальность записывается как `1 NATI Тестовая группа А`; несколько указанных значений — отдельными `NATI`. Значения переносятся из карточки, без определения национальности по имени или результатам ДНК. Запросов к Яндексу и другим геосервисам нет.

## Данные и ограничения

Обработка выполняется **локально в браузере**. Расширение не отправляет запросы от себя, не читает cookies, пароли или токены, не сохраняет древо в хранилище расширения и не обращается к сторонним серверам. Оно наблюдает ответы API древа, которые получает сама страница. Для переходов внутри личного кабинета скрипты подключаются к `https://lk.genotek.ru/*`; кнопка появляется только на странице древа.

Скачанный GEDCOM содержит персональные сведения, семейные связи, примечания и исходные идентификаторы карточек. Не добавляйте реальные выгрузки, ответы API, HAR-файлы или данные авторизации в репозиторий и публичные сообщения об ошибках. Для воспроизведения ошибок используйте вымышленные данные, как в `tests/` и `demo/`.

Фотографии, документы, комментарии, загружаемые отдельными запросами, и результаты ДНК не скачиваются. Экспортируются только доступные текущему профилю сведения, присутствующие в графе. Повторные браки той же пары объединяются в одну семейную запись. В семьях с неизвестным или одинаковым полом партнёров позиции `HUSB`/`WIFE` — ограничение GEDCOM 5.5.1; значение `SEX` не подменяется, а расширение показывает предупреждение.

**Проверено 15.09.2026:** для текущего кода версии 1.0.6 прошёл 51 автоматический тест, проверка оформления, синтаксиса 13 скриптов и манифеста. Тесты проверяют порядок заголовка, `_MARNM`, пользовательские `NOTE`, отсутствие служебных примечаний и семейные ссылки. Проверка реального скачивания после этого изменения формата не выполнялась; границы предыдущей браузерной проверки описаны в [документации](docs/README.md#проверка-в-chrome).

## Если кнопка сообщает об ошибке

- «Данные ещё не получены»: обновите вкладку после установки расширения.
- «Полный запрос древа не подтверждён»: выберите «Близкие», затем «Все», дождитесь загрузки и повторите экспорт. После обновления расширения обязательно обновите вкладку.
- Предупреждение «Счётчик Genotek»: файл содержит фактически полученное число людей; счётчик сайта отличается. Служебные предупреждения в GEDCOM не записываются.
- «Нет доступа»: проверьте авторизацию и доступ к выбранному древу.
- «Изменился формат»: Genotek обновил API; потребуется адаптация расширения.
- «Цикл» или «больше двух родителей»: связи неоднозначны, экспорт останавливается без угадывания семьи.

Сообщения расширения показывают числа и причины ошибок; содержимое древа и токены в консоль не записываются.

## Разработка и проверки

Нужен Node.js 22 или новее. Перед первым запуском команд разработки и после изменения `package-lock.json` установите зависимости командой `npm ci`. Единственная зависимость для разработки — Prettier; само расширение работает без npm-пакетов.

```text
npm ci
npm test
npm run check
npm run demo
```

`npm run check` проверяет оформление через Prettier, затем синтаксис скриптов и манифест. Для автоматического оформления используйте `npm run format`, для отдельной проверки без изменения файлов — `npm run format:check`. Настройки находятся в `.prettierrc.json`; `.gitattributes` закрепляет LF для исходников JavaScript и JSON. Выгружаемый GEDCOM по-прежнему использует CRLF.

Демонстрация: `http://127.0.0.1:8766/genealogical-tree`. Проверка: нажать «Скачать GEDCOM» при выбранных «Близкие», убедиться в переключении на «Все», скачивании 6 людей / 3 семей, затем проверить ошибку сети и восстановление.

Исходники расширения — в `extension/`, тесты — в `tests/`. [Документация проекта](docs/README.md) объясняет работу файлов и функций, форматы данных, проверки и порядок доработки. [Происхождение тестовых примеров](tests/README.md) описано отдельно. Отдельная сборка ZIP не требуется: [GitHub автоматически создаёт архив исходников для каждого релиза](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).

Перед коммитом проверьте список файлов командой `git status --short`. Папки `dist/`, `private/`, выгрузки GEDCOM, HAR, логи, файлы `.env` и ключи исключены через `.gitignore`. Архив релиза содержит файлы репозитория на момент выбранного тега, поэтому в коммите не должно быть личных данных. `.gitignore` не удаляет уже отслеживаемые файлы и не проверяет их содержимое.

# Как устроен Genotek → GEDCOM

Документация для версии **1.0.6**. Здесь описаны установка, работа расширения и назначение всех его функций. Если нужно только установить расширение, достаточно [основного README](../README.md).

## Что делает расширение

На странице древа Genotek появляется кнопка с рисунком листа, стрелкой и надписью GEDCOM. Она находится в правой панели сразу после штатной кнопки скачивания PDF.

Кнопка сохраняет доступное древо в файл `.ged`: GEDCOM 5.5.1, кодировка UTF-8, окончания строк CRLF. В файл входят люди, семейные связи, имена, даты, места, координаты, национальности и доступные примечания.

Расширение получает данные из ответов, которые Genotek уже загружает для своей страницы. Отдельных запросов к аккаунту, Яндексу или другим геосервисам оно не отправляет. Если выбран не весь граф, нажатие кнопки переключает фильтр на «Все»; после этого запрос выполняет сам сайт.

Фотографии, документы, результаты ДНК и сведения, которые сайт загружает отдельными запросами вне ответа графа, не скачиваются. Это самостоятельное расширение, а не официальный продукт Genotek.

## Установка и обновление

1. В GitHub Releases скачайте **Source code (zip)** нужной версии.
2. Распакуйте архив и сохраните полученную папку на компьютере.
3. В Chrome откройте `chrome://extensions` и включите **Режим разработчика**.
4. Нажмите **Загрузить распакованное расширение** и выберите папку `extension` внутри репозитория. В ней лежит `manifest.json`.
5. Откройте древо Genotek в режиме «Древо». Если вкладка уже была открыта, обновите её.
6. Нажмите кнопку GEDCOM в правой панели.

Для обновления замените файлы расширения, нажмите **Перезагрузить** на его карточке в `chrome://extensions`, затем обновите вкладку Genotek. Простого обновления страницы недостаточно, если Chrome ещё использует старую версию расширения.

Сборка и установка пакетов для пользователя не нужны. Минимальная версия Chrome, указанная в манифесте, — 111. Отдельный архив расширения проект не собирает: используется стандартный архив исходников GitHub.

## Как проходит экспорт

1. **Genotek запрашивает древо.** Скрипт `capture.js` замечает подходящий запрос и сообщает, что началась загрузка. Предыдущие данные сразу перестают считаться актуальными.
2. **Приходит ответ.** Расширение проверяет успешность запроса, оставляет только нужные поля и передаёт снимок древа в `content.js`.
3. **Пользователь нажимает GEDCOM.** Если активен другой фильтр, кнопка включает «Все» и ждёт новый ответ.
4. **Проверяется граф.** `graph.js` ищет пропущенных людей, дубли, циклы и неоднозначные связи. Из людей и отношений собираются семьи.
5. **Подготавливаются значения.** `dates.js` обрабатывает даты, `places.js` — места и координаты.
6. **Создаётся GEDCOM.** `gedcom.js` записывает людей, семьи и примечания.
7. **Браузер получает файл.** `content.js` создаёт временный объект с содержимым файла и нажимает скрытую ссылку для скачивания. Пользователь видит результат или объяснение ошибки.

Два скрипта работают в разных средах браузера. `capture.js` загружается в среду страницы, чтобы видеть её `fetch` и `XMLHttpRequest`. Остальные скрипты работают в изолированной среде расширения. Они обмениваются сообщениями через `window.postMessage`.

Манифест подключает скрипты только к `https://lk.genotek.ru/*`. Это позволяет переживать переходы внутри личного кабинета без полной перезагрузки. Кнопка появляется только на маршруте древа и при наличии правой панели.

Модули из `core` умеют работать и в браузере, и в Node.js. В браузере они доступны как `GenotekDates`, `GenotekGraph`, `GenotekPlaces`, `GenotekGedcom`. В Node.js их можно подключить через `require`. Небольшая внешняя функция в начале каждого модуля выбирает нужный способ подключения; сама обработка данных одинакова.

После рефакторинга файлы расширения остались на прежних местах, но крупные функции разделены на небольшие помощники. `normalizeGraph` по порядку проверяет карточки и собирает связи, `convertGraph` вызывает отдельные функции записи, а `content.js` разделяет подготовку экспорта, скачивание и показ результата. Внешние функции модулей и формат входных данных сохранились. Таблицы ниже описывают и доступные снаружи функции, и внутренние помощники; внутренние функции не нужно вызывать из другого модуля.

## Какие данные приходят от Genotek

Текущий запрос страницы — `POST /api/v1/genealogy-graph/{patientId}`. В ответе расширение ожидает объект графа напрямую или внутри поля `data`.

| Поле | Что в нём находится |
| --- | --- |
| `treeId` | Идентификатор текущего древа. Нужен, чтобы не скачать данные другого профиля после переключения. |
| `nodes` | Массив карточек. У каждой записи есть `id`, `type` и объект `card`. |
| `cards_count.full_tree` | Число людей по счётчику сервера. Для старого формата поддерживается также `cards_count.full`. |
| `card.name`, `middleName`, `surname`, `maidenName` | Имена, отчества, фамилии и девичьи фамилии. Несколько значений передаются массивами. |
| `card.gender`, `node.type` | Пол. Сначала используется значение карточки, затем тип узла. |
| `card.birthdate`, `deathdate` | Даты рождения и смерти. Дата может содержать только год или год и месяц. |
| `card.birthplace`, `deathplace` | Исходные текстовые записи мест. |
| `card.birthplaceParsed`, `deathplaceParsed` | Места, разбитые на отдельные поля. |
| `card.ethnicity` | Указанный в карточке «Этнический состав». Переносится как национальность, без вычислений по другим данным. |
| `card.liveOrDead` | Значение `0` означает известный факт смерти. Пустое значение не означает смерть. |
| `card.relatives` | Родственные связи: `id` другого человека и `relationType`: `parent`, `child`, `spouse`. |
| `card.relationships` | Партнёрские связи: `with`, `type`, даты `from` и `to`, признак завершения `finished`. |
| `notes`, `note`, `biography`, `description`, `comment` | Пользовательский текст карточки. Непустые строки записываются отдельными `NOTE` без служебных префиксов. |
| `occupation`, `education` | Род занятий и образование. Непустые строки записываются стандартными тегами `OCCU` и `EDUC`. |

Идентификаторы в примерах и тестах вымышлены. В настоящем GEDCOM сохраняются реальные исходные идентификаторы карточек, поэтому готовый файл содержит персональные данные.

### Почему иногда счётчик не совпадает

Расширение сравнивает фактически полученных людей со счётчиком страницы и счётчиком ответа. Отличие допускается с предупреждением только тогда, когда подтверждён запрос всего древа.

Подтверждением служит исходный POST с `full: true`, без включённых `relatives_only`, `direct_only`, без выбранных `centralCardId`, `cardId` и без поля редактирования `card`. В интерфейсе при экспорте также должен быть активен фильтр «Все».

Само по себе совпадение или несовпадение чисел не доказывает полноту данных на сервере. Расширение не может обнаружить изолированного человека, которого сервер вообще не прислал. При расхождении скачиваются все полученные карточки, а предупреждение остаётся в сообщении расширения. Ссылка на отсутствующего родственника, дубли или цикл всегда останавливают экспорт.

## Получение данных: capture.js

Этот файл не создаёт кнопку и не пишет GEDCOM. Его задача — получить последнюю подходящую загрузку страницы и передать её дальше.

| Функция | Простое объяснение |
| --- | --- |
| `currentRoute()` | Возвращает путь страницы вместе с параметрами адреса. Так снимок привязывается к тому экрану, на котором началась загрузка. |
| `isGraphUrl(value)` | Проверяет адрес запроса. Возвращает `true` только для поддержанных адресов графа на разрешённых HTTPS-хостах. Поиск, редактирование карточек и посторонние сайты не подходят. |
| `publish(nextState)` | Запоминает новое состояние и отправляет его другим скриптам этой же страницы. Добавляет название канала, номер загрузки и маршрут. |
| `selectCardFields(node)` | Копирует из карточки только поля, перечисленные в `CARD_FIELDS`. Для отсутствующей карточки или неподходящего формата возвращает `undefined`. Дальнейшая проверка остановит экспорт для обычного человека; служебные узлы пропускаются. |
| `isFullTreeRequest(method, body)` | Проверяет метод и JSON-тело запроса на признаки полного древа. Возвращает `false` для непонятного тела, другого метода и строки длиннее 65 536 символов. |
| `inspectFetchRequest(input, init)` | Получает сведения о запросе `fetch`. Читает явно переданное тело либо копию объекта `Request`, сохраняя исходный запрос для сайта. Асинхронно возвращает результат проверки полного древа. |
| `begin()` | Начинает новую загрузку: увеличивает её номер, сбрасывает прежний снимок и публикует `loading`. Возвращает номер, который затем используется для проверки ответа. |
| `fail(requestRevision, message)` | Публикует ошибку, только если она относится к последней загрузке. Поздняя ошибка старого запроса не отменяет более новые данные. |
| `httpErrorMessage(status)` | Для HTTP 401/403 сообщает об отсутствии доступа, для остальных ошибок — об ошибке загрузки с номером HTTP-статуса. |
| `complete(requestRevision, response, status, fullTreeRequested)` | Проверяет номер загрузки, HTTP-статус и структуру ответа. Через `selectCardFields` оставляет нужные поля карточек, сохраняет счётчик и признак полного запроса. При успехе публикует `ready`, при проблеме вызывает `fail`. |

`isGraphUrl` принимает хосты `lk2-back.genotek.ru` и `lk.genotek.ru`. Помимо текущего адреса поддержаны прежние формы `/api/v1/patients/{id}/genealogy-graph` и `/api/v1/site/1/relatives/{id}/{id}/genealogy-graph`. Хвосты вроде `/search` или адресов редактирования не подходят.

Список `CARD_FIELDS` — явный перечень полей, разрешённых к передаче. Неизвестные поля верхнего уровня карточки отбрасываются. При добавлении нового экспортируемого поля сначала нужно включить его в этот список. Это не удаляет персональные сведения из разрешённых полей: они нужны для экспорта.

### Обработчики запросов и сообщений

- **Обёртка `window.fetch`** вызывает оригинальный `fetch` с теми же аргументами. Подходящий ответ читается через копию `Response`; страница получает исходный ответ. Ошибки также возвращаются странице.
- **Обёртка `XHR.open`** запоминает метод и признак подходящего адреса в `WeakMap`. Оригинальный `open` продолжает работать.
- **Обёртка `XHR.send`** начинает наблюдение и сохраняет признак полного запроса. Одноразовый обработчик `loadend` читает ответ как JSON или текст, в зависимости от настроек самого сайта. `responseType` не меняется.
- **Обработчик `message`** отвечает на просьбу `request-state` повторной отправкой последнего состояния. Сообщение `clear-state` отменяет снимок и ожидаемые ответы прежнего маршрута, если этот маршрут всё ещё актуален для сохранённого состояния.

Канал называется `genotek-gedcom-v1`. В сообщении есть `type`, `status`, `revision` и `route`; в успешном состоянии добавляются `graph` и `fullTreeRequested`, при ошибке — `message`. Возможные состояния: `idle` — данных нет, `loading` — идёт загрузка, `ready` — снимок готов, `error` — загрузка не удалась.

Обе стороны проверяют источник окна, адрес отправителя и канал. Получатель также проверяет маршрут и номер загрузки. Это защищает от случайно перепутанных сообщений и запоздавших ответов, но не делает страницу доверенным источником: данные графа всё равно проверяются перед экспортом.

## Люди и семьи: graph.js

Граф — это список людей со ссылками друг на друга. Модуль проверяет эти ссылки и превращает их в удобные записи людей и семей.

| Функция | Простое объяснение |
| --- | --- |
| `list(value)` | Приводит значение к массиву: `null` и `undefined` становятся `[]`, массив остаётся массивом, одиночное значение помещается внутрь массива. Пустая строка становится `['']`. |
| `first(value)` | Возвращает первое значение после обработки через `list`. Для пустого списка возвращает `undefined`. |
| `isPlaceholder(id)` | Узнаёт служебные узлы, чьи идентификаторы начинаются с `fake` или `imaginary`. Они нужны рисунку древа, но не считаются людьми. |
| `sexOf(node)` | Переводит пол в `M`, `F` или `U`. Непонятное значение остаётся неизвестным. Используется внутри модуля. |
| `extractGraph(input)` | Берёт граф напрямую или из `input.data`. Проверяет наличие массива `nodes`, иначе сообщает об изменении формата. |
| `readPeople(nodes)` | Пропускает служебные узлы, проверяет карточки, идентификаторы и массивы связей. Возвращает список `people` и таблицу поиска `peopleById`; пустое древо не принимает. |
| `validatePeopleCounts(graph, options, peopleCount)` | Сравнивает число людей со счётчиками. Возвращает предупреждения при подтверждённом полном запросе или останавливает экспорт при недопустимом расхождении и неверном формате счётчика. |
| `comparePeopleById(leftPerson, rightPerson)` | Сравнивает строковые идентификаторы для устойчивого порядка людей. |
| `assignPersonReferences(people)` | Сортирует список на месте и присваивает людям ссылки `@I1@`, `@I2@` и далее. |
| `resolvePerson(peopleById, id)` | Находит человека по исходному идентификатору. Для служебного узла возвращает `null`, для пустой или отсутствующей настоящей ссылки сообщает об ошибке. |
| `createFamilyStore(peopleById)` | Создаёт общий список семей и функцию `getOrCreateFamily`, которая не допускает повторной семьи для тех же взрослых. Возвращает оба значения. |
| `getOrCreateFamily(members)` | Внутри `createFamilyStore` находит или создаёт семью для точного набора взрослых. Назначает `@F…@` и добавляет взрослым обратные ссылки `fams`. |
| `connectRelative(person, relative, context)` | Обрабатывает одну связь `parent`, `child` или `spouse`. Добавляет родителя либо семью супругов; неизвестный тип отмечает предупреждением. |
| `connectRelationship(person, relationship, context)` | Находит партнёра, проверяет ссылку и сохраняет сведения об отношениях в общей семье пары. |
| `connectRelationships(people, context)` | Обходит карточки людей и передаёт каждую родственную и партнёрскую связь соответствующему помощнику. |
| `validateParentHierarchy(people)` | Проверяет ограничение в два родителя и очередью обходит поколения, чтобы найти циклы без рекурсии. |
| `connectChildrenToFamilies(people, peopleById, getOrCreateFamily)` | Для каждого ребёнка находит семью его точного набора родителей, добавляет ребёнка в `children` и обратную ссылку в `famc`. |
| `normalizeGraph(input, options)` | Проверяет структуру и счётчики, собирает родителей, партнёров и детей, находит недопустимые связи. Возвращает `people`, `families` и `warnings`; при ошибке выбрасывает исключение с объяснением. |

Параметр `context` объединяет `peopleById`, `getOrCreateFamily` и общий список `warnings`. Снаружи модуль предоставляет только `normalizeGraph`, `list`, `first` и `isPlaceholder`.

Нормализованная запись человека содержит исходные `id` и `card`, пол `sex`, родителей `parents` и новый номер GEDCOM `xref`. В `famc` находятся ссылки на семьи, где человек ребёнок, в `fams` — где он взрослый участник.

Запись семьи содержит `xref`, взрослых `members`, детей `children` и исходные сведения об отношениях `relationships`. Номера `@I1@` и `@F1@` создаются заново при экспорте; постоянным идентификатором исходной карточки остаётся `id`.

Родителей можно восстановить из связи «родитель» у ребёнка или связи «ребёнок» у взрослого. Супруг человека не назначается вторым родителем автоматически. Поэтому семья с одним известным родителем остаётся такой даже при наличии у этого родителя другого брака.

Проверка циклов выполняется очередью, без рекурсивного обхода. Экспорт останавливается при связи с самим собой, цикле родителей, более чем двух родителях, повторном идентификаторе, неправильной карточке или ссылке на отсутствующего человека. Неизвестные виды родства пропускаются с предупреждением.

## Даты: dates.js

Модуль экспортирует функцию `formatDate(value)` и список сокращений месяцев `MONTHS`.

`formatDate` принимает год числом, строку вида `1900`, `1900-02`, `1900-02-12`, `12.02.1900` или объект с полями `year`, `month`, `day`, `approximate`. Она проверяет календарную дату, включая високосный год, и возвращает текст GEDCOM.

| Функция | Простое объяснение |
| --- | --- |
| `parseDateString(value)` | Убирает пробелы по краям и разбирает строковую дату. Возвращает её части, пустую строку для пустого ввода или `null` для неизвестного формата. |
| `parseDate(value)` | Приводит число, строку или объект к форме, которую можно проверить. Массив и неподходящий тип не принимает. |
| `hasUnknownFields(value)` | Ищет непустые поля, которых нет в списке допустимых частей даты. Не даёт молча потерять неизвестное уточнение. |
| `isLeapYear(year)` | Определяет високосный год по календарному правилу. |
| `maximumDay(year, month)` | Возвращает число дней в выбранном месяце с учётом високосного февраля. |
| `hasValidParts(year, month, day)` | Проверяет целые значения и их диапазоны, наличие месяца при заданном дне и существование даты в календаре. |
| `joinDateParts(year, month, day)` | Собирает только известные части: день, сокращение месяца и год. |
| `formatDate(value)` | Управляет разбором и проверкой, различает пустую и ошибочную дату, добавляет `ABT` для приблизительного года или даты. |

`DATE_FIELDS` перечисляет допустимые поля объекта, `ISO_DATE_PATTERN` и `RUSSIAN_DATE_PATTERN` задают поддержанные строковые формы. `DAYS_IN_MONTH` хранит число дней в обычном году, `MONTHS` — сокращения месяцев GEDCOM.

| Исходное значение | Результат |
| --- | --- |
| `1900` | `1900` |
| `{ year: 1900, month: 2 }` | `FEB 1900` |
| `{ year: 1900, month: 2, day: 12 }` | `12 FEB 1900` |
| `{ year: 1900, approximate: true }` | `ABT 1900` |
| Отсутствующая или пустая дата, в том числе строка из одних пробелов | Пустая строка: событие не получает дату. |
| Нераспознанная строковая дата или обнаруженная календарная ошибка | `null`: значение не выгружается, расширение показывает предупреждение. |

Неизвестные непустые поля объекта даты также дают `null`: расширение не должно молча потерять нераспознанное уточнение. День без месяца не принимается. Неизвестные месяц и день не подставляются.

Есть ограничение обработки повреждённых объектов: например, `{ year: 'unknown' }` считается пустой датой и возвращает `''`, поэтому значение пропускается без предупреждения. Результат `null` означает ошибочную дату и приводит к предупреждению; пустой результат означает отсутствие даты.

## Места и координаты: places.js

Основная функция `normalizePlaces(parsed, raw)` получает разобранные места и исходные текстовые варианты. Она возвращает список записей вида `{ text, coordinates }`. Координаты либо отсутствуют (`null`), либо представлены как `{ latitude: 'N…', longitude: 'E…' }`.

Основным считается первый пригодный вариант: сначала перебираются разобранные данные, потом исходные строки. Координаты не переносятся с другого варианта только ради заполнения полей. Дополнительные места не выгружаются; расширение показывает предупреждение.

| Функция | Простое объяснение |
| --- | --- |
| `list(value)` | Местная вспомогательная функция: возвращает `[]` для `null` и `undefined`, сохраняет массив или оборачивает одиночное значение. Пустая строка остаётся элементом списка. |
| `stringValue(value)` | Для строки убирает пробелы по краям; для другого типа возвращает пустую строку. |
| `comparisonKey(value)` | Делает ключ для сравнения названий: приводит к нижнему регистру, заменяет «ё» на «е» и объединяет повторные пробелы. |
| `createPlaceType([label, pattern, after])` | Готовит описание типа места и правила распознавания типа перед названием или после него. `after` задаёт положение типа в готовом тексте. |
| `describe(value)` | Отделяет название от типа места, узнаёт сокращения вроде «обл» или «г». Возвращает название, найденный тип и читаемый текст. |
| `decimal(value)` | Готовит десятичную запись координаты. Числа вроде `1e-7` разворачивает в обычную запись, чтобы в GEDCOM не попала экспонента. |
| `coordinate(value, limit, positive, negative)` | Проверяет одну координату и её диапазон, затем добавляет сторону света. Например, отрицательная широта получает `S`. При ошибке возвращает `null`. |
| `coordinates(place)` | Проверяет пару `geo_lat` и `geo_lon`: широта до 90°, долгота до 180°. Возвращает обе координаты либо `null`; одиночная координата не экспортируется. |
| `unpack(value)` | Пытается разобрать старую строку, в которой через запятую склеены адресные поля, коды и координаты. Возвращает разобранное место с оставшимися названиями либо `null`. |
| `matchingHints(place, remaining, raw)` | Ищет в исходных строках подсказки типов частей адреса, включая регион, район и населённый пункт. Проверяет совпадение всех частей, чтобы не взять тип от другого одноимённого места. |
| `isRussianPlace(place)` | Определяет российский адрес по коду страны, а при отсутствии кода — по её названию. Явный код другой страны имеет приоритет. |
| `regionTypeFromIsoCode(place)` | Для известного кода российского региона возвращает «область» или «край». Неизвестный код не дополняет предположением. |
| `typeFromMatchingHints(name, hints)` | Выбирает читаемое название из подходящих исходных подсказок, только если они однозначно указывают один тип места. |
| `formatPlaceComponent(place, hints, russian, value, field)` | Оформляет одну часть адреса. Учитывает явно заданный тип, совпадающий исходный адрес, код региона и назначение адресного поля. |
| `removeDuplicateCityRegion(parts)` | Убирает повтор города-региона в массиве частей на месте. Разные уровни с явно указанными типами сохраняет. |
| `joinUniqueParts(parts)` | Убирает пустые части и одинаковые названия, сохраняя первое написание, затем соединяет адрес запятыми. |
| `humanPlace(place, remaining, raw)` | Собирает читаемый адрес из страны, региона, района, города и населённого пункта. Убирает лишние повторы. |
| `legacyPlace(place)` | Сохраняет непонятное место прежним способом: строку оставляет как есть, из объекта собирает непустые строковые значения. |
| `normalizePlace(source, raw)` | Обрабатывает один вариант места: узнаёт его формат, формирует текст и координаты. Если формат не подходит, сохраняет исходное описание, когда это возможно. |
| `normalizePlaces(parsed, raw)` | Объединяет варианты, вызывает обработку каждого места, пропускает пустые строки и строки из одних пробелов, сохраняет исходные склеенные строки и удаляет полностью одинаковые результаты. Это единственная экспортируемая функция модуля. |

Имена полей перечислены в `placeFields`: страна, регион, район, город, городской район, населённый пункт. `knownFields` дополнительно содержит поля с типами, индекс, ISO-коды и координаты. `placeTypes` задаёт узнаваемые сокращения и полные типы. Наборы `oblasts` и `krais` помогают определить область или край по ISO-коду, не угадывая по окончанию названия.

Приоритет оформления одной части адреса: готовое `*_with_type`, тип в самой строке, `*_type_full`, однозначная подсказка из исходного адреса, известный код региона и допустимое уточнение по полю. Одно поле `*_type` само по себе сейчас не используется как подсказка.

В основном читаемом названии не нужны индекс, коды страны и региона, федеральный округ и служебные показатели. При неизвестной структуре они могут остаться в исходном описании или примечании: сохранение непонятных данных важнее их удаления.

Старая склеенная строка распознаётся только при полном наборе признаков: необязательный шестизначный индекс, страна и её ISO-код, код региона, названия, две допустимые координаты и завершающий показатель `qc_geo` от 0 до 5. Федеральный округ может присутствовать или отсутствовать. Простые числа внутри адреса не считаются координатами.

Учебный пример с вымышленными координатами:

```text
300000, Россия, RU, Центральный, RU-TUL, Тульская, Тула, 54.1234567, 37.7654321, 4
```

Основное место получится «Россия, Тульская область, Тула». Если в исходном адресе есть подходящее «г Тула», получится «Россия, Тульская область, город Тула». Сама склеенная строка останется в примечании.

Непустая нераспознанная строка без координат сохраняется как есть, включая пробелы вокруг текста. Строка из одних пробелов, табуляций или переводов строк не считается местом и пропускается. Для частично знакомого объекта неизвестные строковые подробности тоже сохраняются. Нулевые координаты допустимы; пустые значения, неполная пара, посторонний текст и выход за диапазон не создают `MAP`.

## Создание файла: gedcom.js

Из этого модуля доступна функция `convertGraph(graph, options)`. Она вызывает проверку графа, обрабатывает поля и возвращает:

| Результат | Значение |
| --- | --- |
| `text` | Готовый текст файла с завершающей строкой `0 TRLR`. |
| `peopleCount` | Число записанных людей. |
| `familiesCount` | Число записанных семей. |
| `warnings` | Уникальные предупреждения для пользователя. |

В `options` можно передать `expectedCount` — ожидаемое число людей, `fullTreeRequested` — подтверждение полного запроса, `now` — корректный объект `Date` для воспроизводимой даты создания файла. По умолчанию используется текущее время; заголовок использует дату по UTC. Корректность отдельно переданного `now` конвертер не проверяет, поэтому `Invalid Date` передавать нельзя. Признак полного запроса нельзя выставлять только ради обхода ошибки: в расширении он подтверждается по фактическому запросу сайта.

Сам конвертер не читает страницу и не требует наличия счётчика, если вызывающий код его не передал и счётчика нет в графе. В браузере эту дополнительную проверку выполняет `exportOptions`, вызываемая из `saveSnapshot`.

| Функция или метод | Простое объяснение |
| --- | --- |
| `cleanText(value)` | Готовит текст: удаляет служебные управляющие символы, заменяет табуляцию пробелами и приводит переводы строк к одному виду. |
| `serializeValue(value)` | Для объекта возвращает JSON, для обычного значения — очищенный текст. Нужна только для сравнения исходных значений. |
| `uniqueValues(values)` | Убирает пустые значения и повторы после текстового представления. |
| `Writer.constructor()` | Создаёт список будущих строк и кодировщик UTF-8 для проверки длины. |
| `Writer.raw(line)` | Добавляет уже подготовленную служебную строку. Не предназначена для произвольного текста карточки. |
| `Writer.field(level, tag, value)` | Безопасно записывает текстовое поле: обрабатывает `@`, многострочность и длинные значения. |
| `Writer.pointer(level, tag, xref)` | Записывает ссылку на человека, семью или отправителя. В отличие от обычного текста, служебные `@` здесь сохраняются как часть ссылки. |
| `Writer.toString()` | Соединяет строки через CRLF и добавляет завершающий перевод строки. |
| `convertGraph(graph, options)` | Управляет всей записью: заголовок, отправитель, люди, семьи, конец файла. Возвращает текст, счётчики и предупреждения. |
| `userTextValues(value)` | Оставляет только непустые уникальные строки; объекты и другие технические значения не превращаются в JSON. |
| `writeTextFields(writer, tag, value)` | Записывает каждую пользовательскую строку отдельным тегом `NOTE`, `OCCU` или `EDUC`. |
| `hasDateContent(value)` | Проверяет, есть ли в выбранном значении даты содержимое. Используется после отсеивания пустых дат в `writeEvent`. |
| `writeEvent(writer, warnings, { tag, sourceDates, places, label, knownEvent })` | Записывает рождение, смерть, брак или развод. Берёт первую непустую дату и первое место; об остальных вариантах сообщает предупреждением. `knownEvent` позволяет указать известный факт события даже без даты и места. |
| `writeHeader(writer, currentDate)` | Записывает источник и версию экспорта, кодировку, дату, параметры GEDCOM и общую запись отправителя. |
| `cleanNamePart(value)` | Удаляет из части имени переводы строк и буквальные косые черты, которые имеют специальное значение в GEDCOM. |
| `writeName(writer, givenName, middleName, surname, nameType, marriedNames)` | Записывает имя, отчество, фамилию, вид имени и фамилии после брака в `_MARNM`. |
| `writePerson(writer, warnings, person)` | Собирает одну запись `INDI`: варианты имени, пол, события, места, национальности, примечания, исходный ID и ссылки на семьи. |
| `writeFamilyMembers(writer, family)` | Записывает взрослых в позиции `HUSB/WIFE`, в том числе единственного известного родителя. Пол человека не меняет. |
| `hasAmbiguousFamilyRoles(family)` | Определяет случаи неизвестного или одинакового пола взрослых, для которых нужно пояснение технических позиций `HUSB/WIFE`. |
| `uniqueRelationships(relationships)` | Удаляет повторяющиеся сведения об отношениях по полному JSON-представлению. |
| `relationshipDates(relationships, field)` | Собирает уникальные даты `from` или `to` из отношений пары и восстанавливает объекты дат из их текстового представления. |
| `writeFamily(writer, warnings, family)` | Собирает запись `FAM`: взрослых, детей, брак и развод; добавляет нужные предупреждения. |

Помощники записи получают один и тот же `Writer`; функции событий, людей и семей также пополняют общий список `warnings`. Внешний интерфейс модуля — только `convertGraph`. Предупреждения возвращаются вызывающему коду и показываются интерфейсом расширения, но в GEDCOM не записываются.

`Writer.field` удваивает буквальный символ `@`, чтобы текст не стал случайной ссылкой GEDCOM. Новый абзац записывается через `CONT`, продолжение длинной строки — через `CONC`. Каждая строка ограничивается 255 байтами UTF-8 вместе с CRLF; символ Unicode и пара `@@` не разрываются.

### Если данных нет

В GEDCOM эти сведения необязательны. По [спецификации GEDCOM 5.5.1](https://gedcom.io/specifications/ged551.pdf) события и национальность могут отсутствовать в записи человека, а у события не обязательно должны быть и дата, и место.

| Что заполнено в карточке | Что попадёт в файл |
| --- | --- |
| Национальность не заполнена | Тег `NATI` отсутствует. |
| Есть дата рождения, места нет | Блок `BIRT` содержит только `DATE`; `PLAC` и `MAP` не добавляются. |
| Есть место рождения, даты нет | Блок `BIRT` содержит `PLAC` и координаты, если они есть; `DATE` не добавляется. |
| Нет ни даты, ни места рождения | Блок `BIRT` и его вложенные теги целиком отсутствуют. Сам человек сохраняется. |

Пустая строка, строка из одних пробелов, `null` и пустой список не создают эти теги. Пустые варианты перед заполненными пропускаются. Если `formatDate` возвращает `null`, исходная дата не выгружается, а расширение показывает предупреждение. Ограничение для повреждённых объектов даты описано в разделе «Даты».

### Как поля выглядят в GEDCOM

| Сведения | Запись |
| --- | --- |
| Человек | `INDI` |
| Основное имя и фамилия | `NAME`, уточнения `GIVN` и `SURN` |
| Девичья фамилия | Основные `NAME` и `SURN`; текущая фамилия при этом записывается в `_MARNM` |
| Другие имена и фамилии | Дополнительные `NAME` с `TYPE aka` |
| Пол | `SEX M`, `SEX F`, `SEX U` |
| Рождение и смерть | `BIRT`, `DEAT`, внутри — `DATE`, `PLAC` |
| Национальность | Отдельный `NATI` для каждого непустого указанного значения `ethnicity` |
| Исходный идентификатор | `REFN` с `TYPE Genotek card ID` |
| Семья | `FAM`, взрослые `HUSB` и `WIFE`, дети `CHIL` |
| Семья родителей человека | `FAMC` |
| Семья, где человек взрослый | `FAMS` |
| Официальный брак и развод | `MARR`, `DIV` |
| Примечания и биографический текст | Отдельные `NOTE` без служебных префиксов |
| Род занятий и образование | `OCCU`, `EDUC` |

Координаты относятся к месту события, а не к человеку в целом:

```gedcom
1 BIRT
2 PLAC Россия, Тульская область, город Тула
3 MAP
4 LATI N54.1234567
4 LONG E37.7654321
```

Это учебные координаты. Отрицательные широта и долгота в настоящей записи обозначаются `S` и `W`, положительные — `N` и `E`.

Пустые и некорректные даты пропускаются; во втором случае расширение показывает предупреждение. Если точно известно событие, но нет допустимой даты и места, допускается запись вроде `1 DEAT Y`. Если есть дата или место, `Y` не добавляется.

Повторные сведения об отношениях одной пары объединяются. `type: 'official'` создаёт брак; `finished: 1` или `true` у официальной связи — развод. Партнёрство без официального брака создаёт семейную запись без `MARR`. Несколько браков одной и той же пары не превращаются в отдельные семьи; при нескольких датах выгружается первая, а расширение показывает предупреждение.

Если пол участников неизвестен или одинаков, `HUSB/WIFE` служат техническими позициями GEDCOM 5.5.1. Значение `SEX` не подменяется; расширение показывает предупреждение. Данные отправителя в заголовке общие: «Владелец древа Genotek».

## Кнопка и скачивание: content.js

При загрузке файл создаёт один контейнер `genotek-gedcom-export`. Повторное подключение при уже существующем контейнере не создаёт вторую кнопку. Стили находятся внутри Shadow DOM — отдельной области элементов, которая помогает не смешивать оформление сайта и расширения.

Кнопка имеет размер 40×40, скругление 8 px и цвета текущей панели Genotek. Рисунок и надпись GEDCOM находятся в одном SVG 32×32. Их цвет берётся из `currentColor`, поэтому при наведении и выборе клавишей Tab они становятся белыми вместе. Доступное имя кнопки — «Скачать GEDCOM»; при ожидании рисунок целиком заменяется индикатором загрузки.

| Функция | Простое объяснение |
| --- | --- |
| `isTreePage()` | Проверяет, открыт ли маршрут `/genealogical-tree` или его вложенная страница. |
| `findAllTab()` | Находит фильтр «Все» по подписи «Все»/«All» или соответствующему CSS-классу. |
| `expectedPeopleCount()` | Читает число людей возле фильтра «Все». При отсутствии подходящего числа возвращает `undefined`. |
| `show(text, error, extra)` | Показывает сообщение, при необходимости оформляет его как ошибку и добавляет подробности. Текст вставляется как текст, а не как HTML. |
| `positionNotice()` | Размещает сообщение слева от кнопки и ограничивает его ширину и высоту доступным окном. Корректирует положение у края экрана. |
| `stop()` | Завершает ожидание: снимает блокировку кнопки, останавливает таймер и возвращает обычную подпись. Готовое сообщение остаётся видимым. |
| `sameTree()` | Сравнивает идентификатор снимка с идентификатором фильтра «Все», когда оба можно определить. Не позволяет скачать явно другое древо. |
| `exportOptions()` | Проверяет совпадение древа и наличие счётчика. Готовит `expectedCount` и подтверждение полного запроса с учётом того, что «Все» по-прежнему выбран. |
| `downloadGedcom(text)` | Создаёт Blob и временную скрытую ссылку, запускает скачивание `.ged`, удаляет ссылку и через 60 секунд освобождает адрес Blob. |
| `showExportResult(exportResult)` | Показывает число людей и семей, а также предупреждения либо краткое обозначение формата файла. |
| `saveSnapshot()` | Проверяет наличие актуального снимка, вызывает конвертер с `exportOptions()`, запускает скачивание и показывает результат. При исключении показывает ошибку; в обоих случаях завершает ожидание. |
| `waitForFullTree(allPeopleTab)` | Сбрасывает частичный снимок, включает ожидание с тайм-аутом 30 секунд, блокирует кнопку и нажимает фильтр «Все». |
| `handleDownloadClick()` | Обрабатывает нажатие GEDCOM: выбирает ожидание полного древа, сообщение о загрузке или отсутствующих данных либо экспорт готового снимка. |
| `isCurrentCapturedState(event, capturedState)` | Проверяет окно, отправителя, канал, тип сообщения, маршрут и целый номер загрузки. Отбрасывает чужие и устаревшие состояния. |
| `receiveCapturedState(event)` | Принимает проверенное состояние, обновляет снимок и признаки загрузки, показывает ошибку или планирует ожидающий экспорт на следующий кадр. |
| `attachButtonToToolbar(toolbar)` | Ставит кнопку после PDF. Если PDF не найден, при первом добавлении в панель использует место перед меню или масштабированием. |
| `mount()` | Проверяет смену маршрута и наличие панели. Устанавливает кнопку после PDF, восстанавливает её при перерисовке страницы и убирает при выходе из древа. |

### Что хранится в памяти

`snapshot` — последние полученные данные; `revision` — номер их загрузки; `loading` — идёт ли загрузка; `pending` — нужно ли автоматически скачать после переключения на «Все». `fullTreeRequested` хранит подтверждение полного запроса, `timeout` — таймер ожидания, `route` — текущий маршрут.

Это переменные открытой страницы, а не постоянное хранилище. Новый запрос, смена маршрута или ошибка отменяют использование старого снимка.

### Обработчики интерфейса

- **Нажатие GEDCOM** передаётся `handleDownloadClick`. Переключение на «Все» и ожидание вынесены в `waitForFullTree`; готовый снимок экспортирует `saveSnapshot`.
- **Входящее сообщение `state`** обрабатывает `receiveCapturedState`, используя проверку `isCurrentCapturedState`. Когда ожидание заканчивается успешным ответом, экспорт ставится на следующий кадр браузера.
- **Нажатие крестика** скрывает сообщение, не меняя древо.
- **Наблюдатель `MutationObserver`** замечает изменения элементов сайта и вызывает `mount`. Флаг `scheduled` объединяет частые изменения в одну проверку на кадр.
- **Интервал раз в секунду** дополнительно вызывает `mount`, чтобы заметить смену маршрута или восстановить панель.
- **Изменение размера окна** вызывает `positionNotice`.
- **Таймер после скачивания** через 60 секунд освобождает временный адрес файла. Скрытая ссылка удаляется сразу после нажатия.

Для встраивания используются `.tree__actions`, `.tree__actions-btn`, `.icon-download`, `.tree__actions-btn-box` и `.tree__zoom`. Если PDF-кнопка не найдена, расширение пытается встать перед меню или масштабированием. Если самой панели нет, кнопка не показывается.

Фильтры находятся через `.graph-mode-filters__tab`, подпись — через `.graph-mode-filters__tab-label`, число — через `.graph-mode-filters__tab-number`, активность — по `graph-mode-filters__tab--active`. Эти места стоит проверять в первую очередь, если Genotek изменит интерфейс.

Файл называется `genotek-tree-YYYY-MM-DD.ged`; дата берётся по UTC. Сообщение «Файл передан на скачивание» означает, что ссылка нажата: расширение не использует разрешение `downloads` и не отслеживает окончание записи файла браузером.

## Как запускать проект и пользоваться конвертером

Для разработки нужен Node.js 22 или новее. В корне репозитория один раз выполните `npm ci`, чтобы установить Prettier из `package-lock.json`. Повторяйте установку после изменения файла зависимостей. Для установки самого расширения в Chrome Node.js и эти команды не нужны.

```text
npm ci
npm test
npm run check
npm run demo
```

| Команда | Что делает |
| --- | --- |
| `npm ci` | Устанавливает зафиксированные зависимости в `node_modules`. Нужна для команд Prettier; исходники расширения не собирает. |
| `npm test` | Запускает 50 тестов встроенным средством Node.js. |
| `npm run format` | Применяет правила Prettier к перечисленным в команде файлам. Изменяет их оформление. |
| `npm run format:check` | Проверяет оформление без изменения файлов. |
| `npm run check` | Сначала запускает `format:check`, затем проверяет синтаксис и манифест через `scripts/check.cjs`. |
| `npm run demo` | Запускает локальный сервер до остановки, обычно клавишами Ctrl+C. |

Установка npm-пакетов нужна только для Prettier: сами тесты, демонстрация и расширение от него не зависят. В `package.json` и `package-lock.json` зафиксирован Prettier 3.9.6. Папка `node_modules` исключена из Git.

### Оформление исходников

Правила находятся в `.prettierrc.json`: отступ в два пробела, одинарные кавычки, точки с запятой, завершающие запятые, скобки у параметров стрелочных функций и предпочтительная ширина строки 100 символов. Для исходников выбран LF. `.gitattributes` закрепляет LF для `.js`, `.cjs` и `.json`; это не меняет CRLF в готовом GEDCOM, который формирует `Writer.toString()`.

Команды Prettier охватывают `.prettierrc.json`, `package.json`, JavaScript в `extension/` и `demo/`, CJS в `scripts/` и `tests/`. Markdown, HTML, `manifest.json` и `package-lock.json` в эту команду не включены. После автоматического оформления просмотрите diff перед коммитом.

### Демо и отдельный вызов конвертера

Демонстрация доступна по адресу `http://127.0.0.1:8766/genealogical-tree`. Порт можно изменить переменной окружения `GENOTEK_DEMO_PORT`.

Конвертер можно использовать из Node.js отдельно от Chrome. Например, выполнить такой код из корня репозитория в интерактивном Node.js:

```js
const { convertGraph } = require('./extension/core/gedcom.js');
const { blendedFamily } = require('./tests/fixtures.cjs');

const result = convertGraph(blendedFamily());
console.log(result.peopleCount, result.familiesCount); // 6 3
console.log(result.warnings);
```

`result.text` содержит готовый GEDCOM. В этом примере используются только вымышленные люди. Для своей интеграции нужно передать граф описанной выше структуры и обработать возможное исключение.

## Демонстрация и служебные скрипты

В `demo/index.html` скрипты идут в порядке: имитация сайта, перехватчик, даты, граф, места, GEDCOM, кнопка. Благодаря этому демонстрация использует те же файлы расширения, что и установленная версия.

В `demo/demo.js`:

- **Обёртка `window.fetch`** перехватывает только вымышленный адрес графа. Через небольшую задержку возвращает локальные тестовые данные или ошибку 503. В режиме «Близкие» оставляет три карточки; при проверке расхождения увеличивает счётчик. На реальный сервер Genotek этот запрос не уходит.
- **Обработчик `DOMContentLoaded`** связывает элементы страницы с действиями и запускает первую загрузку.
- **`loadGraph()`** запрашивает демонстрационное древо, обновляет счётчик и рисует карточки. При ошибке меняет статус.
- **Обработчики фильтров** меняют режим и активную вкладку, затем вызывают `loadGraph`.
- **Кнопка завышения счётчика** включает расхождение на единицу и перезагружает данные.
- **Кнопка ошибки сети** включает ответ 503 и перезагружает данные.
- **Кнопка восстановления** снимает оба искусственных сбоя и снова загружает данные.

В `scripts/demo-server.cjs` обработчик HTTP-запроса отдаёт `blendedFamily()` по `/demo/fixture`, страницу по `/` и `/genealogical-tree`, остальные файлы — только из явного списка `allowedFiles`. Для другого пути возвращает 404. Сервер слушает только `127.0.0.1`, отключает кэширование ответов и не предоставляет доступ к произвольным файлам репозитория. Обработчик запуска печатает адрес демонстрации.

В `scripts/check.cjs` нет отдельных именованных функций: проверка выполняется последовательно. Сначала проверяются Manifest V3, отсутствие полей `permissions` и `host_permissions`, точный список сайтов и наличие подключённых файлов. Затем `.js` и `.cjs` рекурсивно ищутся только в четырёх папках из `sourceDirectories`: `demo`, `extension`, `scripts` и `tests`. Каждый найденный файл проверяется командой `node --check`; `node_modules` не обходится. Ошибка останавливает команду. Эта проверка не запускает браузер и не сравнивает номера версий между файлами.

- В Chrome демонстрация переключилась с «Близкие» на «Все» и скачала шесть вымышленных людей в три семьи. При завышенном счётчике файл скачался с предупреждением; после HTTP 503 старый снимок не скачался. После восстановления экспорт снова прошёл без предупреждения.
- Все три скачанных тестовых файла полностью совпали с результатом прежнего и нового конвертера при той же дате экспорта. Проверены места, координаты, национальность, CRLF и конец файла. При выборе кнопки клавишей Tab рисунок и GEDCOM стали белыми вместе, подсказка появилась.
- На авторизованном древе установленное расширение переключило фильтр на «Все» и скачало GEDCOM. Проверены размещение единственной кнопки после PDF, размер 40×40, UTF-8, длины строк, семейные и обратные ссылки, координаты, национальность и отсутствие пустых тегов. Данные аккаунта и его статистика в документацию и тесты не переносились.

В проверенных сценариях штатного экспорта регрессий не обнаружено. Строгого совпадения на любом произвольном JavaScript-вводе нет: при искусственном `options.now = new Date(NaN)` текст ошибочной даты заголовка отличается; оба варианта некорректны. Расширение этот параметр не передаёт. Проверка в Chrome подтверждает описанные сценарии, но не заменяет проверку будущих изменений API Genotek.

## Где вносить изменения

| Что требуется | Что менять и проверять |
| --- | --- |
| Новое поле карточки | Добавить его в `CARD_FIELDS`, затем обработать в `gedcom.js`. Проверить передачу в `capture.test.cjs` и результат в `gedcom.test.cjs`. |
| Новый формат адреса | Изменить `places.js`, добавить вымышленный пример в `places.test.cjs`. Убедиться, что непонятные адреса продолжают сохраняться. |
| Новый формат даты | Изменить `formatDate` и проверки дат в `gedcom.test.cjs`. Сохранить различие между пустой и нераспознанной датой. |
| Другие правила родства | Изменить `normalizeGraph` и при необходимости запись семей в `gedcom.js`. Проверить всех родителей и обратные ссылки. |
| Новый адрес API или структура ответа | Проверить `isGraphUrl`, `isFullTreeRequest`, `complete` и тесты перехвата. |
| Изменённый интерфейс Genotek | Исправить поиск панели и фильтров в `content.js`, обновить демо и проверить браузером. |
| Оформление кнопки | Изменить SVG и стили в `content.js`. Сохранить доступное имя, размер, индикатор ожидания и согласованные цвета. |
| Новая версия расширения | Согласованно обновить `extension/manifest.json`, `package.json`, версию проекта и корневого пакета в `package-lock.json`, значение `SOUR/VERS` в `writeHeader` и документацию. |

Перед завершением доработки выполните `npm test`, `npm run check` и `git diff --check`. Для интерфейсных изменений нужна проверка в Chrome. Используйте вымышленные случаи, а не копии личных карточек.

Для релиза коммит с готовыми файлами отмечается тегом, по нему создаётся GitHub Release. Пользователи скачивают стандартный **Source code (zip)** и выбирают папку `extension`. Дополнительной сборки и ZIP-файла в репозитории не требуется.

## Частые проблемы

| Что видно | Что сделать |
| --- | --- |
| Кнопки нет | Проверить, что расширение включено, открыта страница именно в режиме «Древо» и есть правая панель. После установки обновить вкладку. Если сайт изменил панель, проверить селекторы в `content.js`. |
| «Данные древа ещё не получены» | После перезагрузки расширения обновить страницу. При необходимости переключить «Близкие» → «Все» и дождаться ответа. |
| «Полный запрос древа не подтверждён» | Включить «Все» через переключение фильтра и дождаться новой загрузки. Не подменять счётчик и не отключать проверку. |
| Предупреждение о счётчике | Файл содержит полученные карточки; серверный счётчик отличается. Предупреждение показано интерфейсом и не записано в GEDCOM. |
| Ошибка доступа, HTTP 401/403 | Проверить вход в Genotek и доступ к древу, затем обновить страницу. |
| Данные другого профиля | Обновить страницу после переключения древа. |
| Ссылка на отсутствующего человека, цикл или более двух родителей | Проверить исходные связи. Расширение останавливает экспорт, чтобы не создавать вымышленную семью. |
| Непонятный адрес остался длинной строкой | Формат не распознан надёжно. Добавить отдельный искусственный пример и правило разбора, сохранив прежний текст при неудаче. |
| Не появились координаты | Проверить наличие обеих допустимых координат у основного места. Расширение не получает недостающие координаты из геосервисов. |
| Не появилась национальность | Проверить, что ответ графа содержит непустой строковый массив `ethnicity`. По имени или ДНК она не определяется. |

## Персональные данные и лицензия

В расширении нет сервера, телеметрии, чтения cookies, паролей и токенов, постоянного хранилища древа, разрешений `downloads` или `debugger`. Передаются только разрешённые поля ответа графа. Ошибки показываются текстом, без вывода содержимого древа в консоль.

Готовый GEDCOM содержит личные сведения, семейные связи и исходные идентификаторы. Реальные выгрузки, HAR, ответы API и данные авторизации не должны попадать в репозиторий или публичные сообщения об ошибках. `.gitignore` помогает исключить отдельные файлы, но не очищает уже отслеживаемые файлы, текст примеров или историю Git.
